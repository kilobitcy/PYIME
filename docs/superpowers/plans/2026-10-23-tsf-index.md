# 自带 TSF 前端:三份计划的执行顺序

设计:`docs/superpowers/specs/2026-10-23-tsf-frontend-design.md`。三份计划互有文件交叠(`scripts/package.sh`、`installer/pyime.nsi`),**必须按下表顺序执行**,不可并行。

| 顺序 | 计划 · 任务 | 交付 / 验收 | 为何排在这里 |
|---|---|---|---|
| 1 | A(`2026-10-23-tsf-dll.md`)Task 1–2 | `tsf/` 收编;`PYIME-0.0.0-tsfstep1-setup.exe` 装进现有 PIME,用户实机确认无回归 | 只换 DLL 来源,行为不变 |
| 2 | B(`2026-10-23-tsf-server.md`)Task 1–9 | `pyime-server.exe`(改名、监护、管道 worker、原子写、pipe-cli);`PYIME-0.0.0-pipecheck-setup.exe` + `pipecheck.txt` 实机验收 | B Task 9 仍走旧附加包安装器,须在 A Task 6(DLL 改名、旧附加包失效)之前 |
| 3 | A Task 3–7 | DLL 改连新管道、超时退避、断线清理、日志、新 GUID;`dist/tsf-dev.zip` + `tsf-dev.txt` 实机验收 | 依赖 B Task 1 的 `pyime-server.exe` 与 B 的管道服务端 |
| 4 | C(`2026-10-23-tsf-installer.md`)Task 1–4 | 独立安装器、`package.sh`、备用脚本、`test-kit/tsf.txt` 实机验收 | 依赖 A、B 全部产物;移走 `pime/test-kit` 前 A 已用完 |
| 5 | C Task 5 | 删除 PIME 遗留(删除清单先经用户确认)、改写 CLAUDE.md、出 0.1.15 | 发布 0.1.15 前须先问用户(push/tag/release) |

每个"实机验收"点都要等用户在 Win11 上按清单测完并回报通过,才进入下一行。

## 已知中间状态
- 顺序 3 的 A Task 6 之后到顺序 4 完成前,`package.sh` 出不了可用的旧附加包;用户日常仍用已安装的 0.1.14/测试包。
- 验证期新旧两个输入法同名"PYIME 拼音"并存(新的在语言列表末尾);新旧服务端共用 `user.txt` 时,一方会因"外部修改保护"暂停写盘,学习只留内存——预期现象,迁移后消失。
