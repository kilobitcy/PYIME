# 符号候选(汉字后附加符号) 设计

日期:2026-10-22 · 基于 main = 85c0667

## 背景

- 需求:`shang` 候选里出现 `↑`,`er` 候选里出现 `②`;即常用符号能经拼音直接打出。
- rime-ice 自带数据不合用:`opencc/emoji.txt` 里"上"对应 `⬆️`、"二"对应 `2️⃣`(彩色 emoji,
  非所需字符);`others.txt` 只有 `°`、`±`、`℃` 等少数几条。故自建精简符号表。
- 不收 emoji(CLAUDE.md:不做表情包)。

## 方案

按**词**挂符号:候选文字精确命中符号表时,把符号插在该候选紧后面。
否决:按拼音挂(`shang → ↑`)——模糊写法要逐个配,且"商/伤"等同音候选无从区分。

## 1. 符号表 `installer/symbols.txt`

- 一行 `词⇥符号1 符号2 …`,符号间空格分隔;`#` 开头为注释,`trim` 后为空的行跳过;格式不对的行跳过;
  去掉文件头 UTF-8 BOM(记事本保存常带),行尾 `\r` 由 `trim` 吞掉。
- 同一词重复出现时以首行为准,后面的行忽略(不合并,免得多出的符号永远不可见)。
- 收录原则(经复核收紧,已与用户确认):只收"打这个词多半就是为了要符号"的条目——
  箭头、带圈数字 `①–⑳`、罗马数字、数学关系与运算(`± × ÷ ≈ ≠ ≤ ≥ ∞ √ ℃ ‰`)、希腊字母、
  货币名、勾叉(`✓ ✗`)、几何图形名、`© ™ ® … ※` 等。
- 不收:键盘可直接打的 ASCII 符号(`# & @ % $`)、单位缩写(`km kg`)、标点名(书名号、引号等,
  与标点键的成对补全逻辑重复),以及以普通词义为主的高频词(和、第、号、点、方、元、角、度、心、
  对、错、因为、所以、注意、参考、注册等),免得把这些词的第 2、3 名挤后。
- 例外:上/下/左/右、一至十是用户点名的需求,保留;`破折号 ——`、`间隔号 ·` 键盘不便直接打,经用户确认保留。初稿约 150 条。
- 打包:`pyime.nsi` 增 `File "symbols.txt"`,与 `pyime.dict` 同装在 `server.exe` 目录;
  卸载时随 `pyime` 目录整体删除(已有 `RMDir /r`)。文件缺失即不出符号(删掉即关闭功能)。

## 2. 引擎(`pyime-engine`)

- 新模块 `symbol.rs`:`Symbols::parse(&str) -> Symbols`,`Symbols::get(&str) -> &[String]`。
- `Engine::set_symbols(Symbols)`;`Source` 新增 `Symbol`,同步给 `tests/regression.rs` 的 `bucket()`
  穷举 `match` 加 `Symbol => "符号"` 分支(否则编译失败)。
- `candidates_after` 中,在 `place_english` 与 ASCII 改标 `English` 之后、`truncate` 之前调用
  `place_symbols`:
  - 宿主条件:`consumed == input.len()`,且其文字在 `words` 里有一条"从 0 到 `input.len()`、
    `fuzzy == 0`、非残缺音节"的词(精确整段词,含用户短语)。只靠拼出来的整句、模糊词、
    残缺音节补全的词(`sh` → 上)都不挂;
  - 每个命中的候选后插入**最多 2 个**符号,按表内顺序;
  - 已在列表中的符号文字跳过,不重复;
  - 符号候选:`consumed = input.len()`,`fuzzy`/`pairs` 为 0,`parts` 为空,`source = Symbol`;
    `cuts` 复制宿主候选的,免得高亮移到符号时组字串 `er'shi` 变 `ershi` 抖动。
  - 必须排在 ASCII 改标 `English` 之后:`%`、`$` 等 ASCII 符号来源须保持 `Symbol`(否则会被当英文学习)。
- 模糊匹配得到的候选**不**挂符号(`san` 只出 `③`,不出模糊来的"上"后的 `↑`),避免叠加噪声。
- 只吃前缀的候选(`Prefix`)不挂:`shangban` 不出 `↑`。

## 3. 后端(`pyime-backend`)

- `ime.rs` 启动时读 `server.exe` 同目录 `symbols.txt`(仿 `load_english`),读失败写日志后跳过。
- **选中符号不学习**:`session.rs` 的 `select` 对 `Source::Symbol` 不调 `ime.learn`、不入 `learned`;
  分段选词中任一段为符号时,末尾的整句学习(`segments > 1` 分支)也跳过。
  否则 `shang → ↑` 会被学成用户词,把"上"挤下首位。
  - 符号候选吃满剩余输入,必是本次组词的最后一段,故在 `select` 内用局部变量判断即可,
    无需跨按键的会话标志(也就不存在 `flush_raw` 漏复位的问题)。
- **符号不进上文**:上屏文字以符号结尾(符号必为最后一段),`context` 清空,
  免得下次 `learn_next(prev="…↑", …)` 往 `user.txt` 写以符号为上文的搭配。
- 同串拼音改选(先选"上",退格重打 `shang` 改选 `↑`)沿用 `finish_commit` 现有逻辑,撤回"上"的学习,属预期。
- 输入日志照常记录选中项(便于观察符号是否被用)。

## 4. 测试

- 引擎单测:
  - `shang` → `↑` 紧跟"上"之后;
  - `er` → "二"之后依次 `②`、`Ⅱ`,第 3 个符号不出现;
  - `shangban` 不出 `↑`;
  - 模糊输入命中的候选不挂符号(`san` 中模糊来的"上"后无 `↑`);
  - 符号已在列表中时不重复;英文候选不挂符号;ASCII 符号(`%`)来源仍为 `Symbol`;
  - 符号候选的 `cuts` 与宿主相同;
  - 符号表解析:注释、空行、坏行、BOM、CRLF、重复词以首行为准。
  - 残缺音节补全出的宿主不挂(`sh` 出"上"但无 `↑`);
- 后端单测:选中符号后上屏正确、用户词表无新增;分段中含符号时整句不学;选符号后上文不含符号。

## 5. 已知代价与风险

- 有符号的词后会多出 1–2 个候选,原第 2、3 名后移;已靠收紧符号表与只挂精确候选把影响限制在
  "上/下/左/右、一至十"等少数高频字上(用户已接受)。回归测试默认不载符号表,数字看不出此影响;
  需要时可另加 `PYIME_SYM` 变量专测(本次不做)。
- 候选窗由补丁版 DLL 用 GDI 绘制,字体缺字形时 `✓ ★` 等可能显示为方框,需 Windows 实机确认;
  如缺字,另行在 DLL 补字体回退(不在本次范围)。
